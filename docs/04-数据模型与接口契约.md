# 数据模型与接口契约

本章把已确认的业务流程转成前后端共同遵守的数据和通信约定。以下字段、状态与端点是待实现的 V1 设计，不表示已有服务或第三方平台已具备这些能力。具体 AI 供应商和房源获取方式不进入公共业务模型，由服务端适配。

## 1. 全局约定

2026-11-03 接入说明：认证使用 SDK 原生 `/api/auth/*`，新增 `/api/auth/token` 与 `/api/auth/jwks`；客户端使用 JWT 直连 Go `/v1/*`，身份复核使用 Go `/v1/session`。原网关 `/api/session` 与签名代理在迁移期保留，不实现下文占位的独立 `/v1/auth/login/refresh/logout`。当前联调命令桥、已支持接口和待迁移 REST 范围见第 06、07 章。

| 项目 | 约定 |
| --- | --- |
| 接口与标识 | 云端统一 `/v1`，JSON 使用 camelCase；业务 ID 使用不透明字符串，前端不解析 ID 含义 |
| 归属 | 用户数据带 `ownerUserId`；身份从服务端认证上下文取得，不能信任请求体里的归属字段。资源目录由管理员发布，按资源使用权限另行校验 |
| 时间 | 时间点使用 UTC RFC 3339 字符串，界面按用户时区展示；持续时间使用 `durationMs` |
| 金额 | 房源总价使用 `priceCents` 整数分与 `currency: "CNY"`；原始“万元”在导入边界转换，未知金额为 `null`，不写成 0 |
| 面积 | `areaSqm` 使用平方米，最多两位小数；后端使用定点数存储，输入必须为正数 |
| 更新 | 可修改实体带递增 `version`；更新请求必须带 `expectedVersion`，版本不符返回 409 |
| 删除 | 不删除仍被任务快照引用的资源版本和媒体；被引用的房源归档后仍保留历史任务信息 |
| 列表 | `?cursor=...&limit=20`，服务端限制最大 100；返回 `{items, nextCursor}`，末页 `nextCursor: null`。同一游标保持查询条件不变 |
| 敏感信息 | 列表不返回平台 Cookie、口令、供应商密钥或原始声音训练文件；下载地址按权限临时签发 |

V1 按用户归属隔离，不先建立企业组织和套餐体系。管理员权限独立校验，不能通过传入其他用户 ID 获得访问权限。跨实体关联也必须检查归属，不能只验证主记录。

## 2. 实体与关联

除 User 和全局资源目录外，用户业务实体默认具有 `id / ownerUserId / createdAt / updatedAt`；可修改实体再包含整数 `version`。资源引用中的 `version` 是不可变的资源版本字符串，与业务记录的乐观锁版本分开。大文件放对象存储，数据库保存元数据与对象键，不能把临时签名 URL 当作永久资源标识。

| 实体 | 核心字段与约束 |
| --- | --- |
| User | `displayName, avatarAssetId, status`；认证凭据不进入公开用户 DTO |
| Device | `name, os, arch, appVersion, runtimeVersions, lastSeenAt, status`；设备与登录用户绑定，解绑后拒绝领取新任务 |
| PlatformAccount | `deviceId, platform, platformUserReference, nickname, loginStatus, lastCheckedAt, unboundAt`；云端只存绑定与状态，本地保存会话 |
| AgentProfile | `name, brokerage, city, regions, introduction, contactInfo, avatarAssetId, defaults`；`defaults` 保存模式、模板、声音、形象、审核开关 |
| Voice | `name, providerReference, status, sampleAssetId, authorizationRecordId`；克隆音色关联本人授权记录，供应商引用由云端持有 |
| Avatar | `name, sourceAssetIds, providerReference, status, previewAssetId, authorizationRecordId`；独立于声音管理，失败可显示原因 |
| Property | `source, propertyNumber, title, city, district, community, priceCents, currency, areaSqm, layout, description, sellingPoints, lastVerifiedAt, importStatus, archivedAt` |
| Asset | `kind, storageLocation, objectKey, localReference, mimeType, sizeBytes, sha256, status`；区分云端对象与设备本地文件，不把任意本地绝对路径交给网页使用 |
| PropertyAsset | `propertyId, assetId, role, sortOrder, sourceReference`；将房源与视频、图片关联，同一素材可保留来源与可使用范围 |
| ResourceVersion | `resourceId, type, name, version, manifestHash, packageHash, sizeBytes, dependencies, compatibleModes, minClientVersion, publishStatus`；已发布版本不可覆盖 |
| ImportJob | `deviceId, source, inputType, status, counts`；子项记录 `propertyNumber, status, propertyId, errorCode, errorMessage`，逐条保留成功、重复和失败结果 |
| ProductionBatch | `deviceId, configSnapshot, submittedPropertyIds, status`；任务数量、完成数、失败数、待审核数从子任务派生，不由客户端回写 |
| ProductionTask | `batchId, propertyId, propertySnapshot, configSnapshot, status, stage, attempt, productionRevision, scriptRevision, approvedRevision, script, audioAssetId, avatarVideoAssetId, renderedVideoAssetId, coverAssetId, error, completedAt` |
| ProductionRevision | `taskId, revision, scriptRevision, scriptSnapshot, configSnapshot, assetRefs, status`；`(taskId, revision)` 唯一，已完成修订不可覆盖，保留历史完整原文和成果 |
| PublishTask | `productionTaskId, productionRevision, deviceId, platform, accountId, title, description, hashtags, coverAssetId, status, platformDraftId, platformPostId, resultEvidence, publishedAt, error` |
| ProviderOperation | `targetType, targetId, targetRevision, operationType, provider, providerRequestId, status, resultRefs, error`；状态为 `pending / submitted / running / succeeded / failed / unknown / canceled`，保存异步供应商调用记录 |
| LeadAnalysisJob | `deviceId, platform, sourceVideoReference, analysisScope, sourcePermission, status, counts, error`；线索带 `analysisJobId` 追溯分析来源 |
| Lead | `sourcePlatform, sourceVideoReference, commentText, sourcePermission, intentLevel, aiSummary, budget, region, housingRequirements, contactPermission, followupStatus`；AI 推断与原始评论分别保留 |
| Followup | `leadId, note, status, createdBy`；追加跟进记录，不用新备注覆盖历史 |

房源在同一用户内按 `(source, propertyNumber)` 去重；来源不同不能仅凭相同编号合并。声音、形象及素材保存授权对象、用途、确认时间和授权版本，撤回后停止新的使用，历史记录的清理按保留策略执行。

关联关系为：一个批次包含多个生产任务，每个生产任务对应一套房源；一个生产任务可以对应多个平台发布任务；一条线索具有多条跟进记录。媒体统一通过 Asset 引用，避免为音频、视频、封面重复设计文件上传协议。

`publishStatus` 是房源列表的派生展示字段：存在关联房源的 `PublishTask.status = published` 才属于“已发布过”。生产成功、保存系统草稿、保存平台草稿均不满足该条件。

## 3. 配置与快照

前端提交的是选择，云端保存的是经过验证的快照：

```ts
type VideoMode = 'voiceover' | 'avatar';
type ResourceRef = { id: string; version: string };

interface ProductionConfig {
  propertyIds: string[];
  videoMode: VideoMode;
  promptTemplate: ResourceRef;
  videoTemplate: ResourceRef;
  styleTemplate: ResourceRef;
  coverTemplate: ResourceRef;
  subtitleTemplate?: ResourceRef;
  voiceId: string;
  avatarId?: string;
  requireScriptReview: boolean;
  aspectRatio: '9:16' | '16:9';
  outputResolution: '720p' | '1080p';
}
```

服务端校验房源归属、素材准备状态、声音和形象状态、资源已发布版本与模式兼容性。露脸模式必须有可用形象；纯口播模式忽略并清除任务快照中的 `avatarId`。属性列表不能为空且不得重复，数量上限由当前能力配置返回，超限整批拒绝，不能静默截断。

创建时冻结房源必要信息、素材引用及哈希、模板版本、渲染参数、声音/形象引用；提示词实际内容由云端留存快照，客户端按业务需要获取说明。批次共用一套生成配置，各子任务保留可独立恢复的有效快照。之后修改房源、默认配置或模板不会改变已创建任务。

只有当前用户有权访问且完成校验的资源才能进入任务；选择器对未安装资源先下载，安装成功后才确认选中。云端创建任务仍校验权限、版本与兼容性，执行设备开始对应阶段前再次检查准确版本；缺失时显示等待资源或明确失败，不自动替换为最新版。

## 4. 任务与审核状态

生产任务将执行状态与业务阶段分开：

| 字段 | 取值 |
| --- | --- |
| `status` | `queued / running / awaiting_review / succeeded / failed / canceled` |
| `stage` | `prepare / script / tts / avatar / render / cover` |

字幕属于 `render` 阶段，纯口播跳过 `avatar`。排队、失败和取消仍保留当前阶段，错误包含 `code / message / retryable / stage`。仅在引擎能提供可靠进度时返回百分比，否则仅返回阶段，不用定时器制造真实进度。

正常转换为 `queued → running → succeeded`；需要审核时，在文案生成后进入 `awaiting_review`，审核通过后才允许进入 TTS。各阶段失败进入 `failed`，通过合法重试回到 `queued`。终态不会被迟到的旧执行结果覆盖，取消、租约和执行权规则见系统架构章。

文案每次修改或重新生成都递增 `scriptRevision`。审核请求带 `expectedVersion` 和 `scriptRevision`；服务端只批准当前修订，并写入 `approvedRevision`。`productionRevision` 从 1 开始，用来标记一套有效产物；任何需要废弃下游产物的输入变化都递增该值。已开始下游处理时修改文案，先终止旧执行尝试或等待其结束，以新修订隔离旧回调，再清除任务当前使用的下游产物引用，重置审核与后续阶段；历史保存在 ProductionRevision，不直接删除。终止执行尝试不等于把整个任务改为 `canceled`；整个任务一旦取消不能重试或审核恢复，只能新建。旧修订发布记录不改写，新的发布任务只能引用已完成的明确产物修订。

批次状态由子任务聚合为 `queued / running / awaiting_review / succeeded / partial_failed / failed / canceled`。优先级：存在运行或排队任务则为 `running`（全部排队为 `queued`）；无执行中任务但存在待审核则为 `awaiting_review`；全部成功为 `succeeded`，全部取消为 `canceled`，全部失败为 `failed`，其他终态混合为 `partial_failed`，同时展示成功、失败及取消数量。

发布状态使用 `queued / running / draft_saved / published / failed / unknown / canceled`。平台明确确认才写入 `draft_saved` 或 `published`；请求超时、浏览器中断且无法判断结果时写入 `unknown`，先查询或人工确认，不能直接重传。平台不支持草稿时返回能力不可用，保留系统待发布内容，不伪造草稿成功。

## 5. 云端 REST 接口

端点中的操作名表示业务意图，所有命令均由服务端判断当前状态是否合法。列表端点支持统一分页，详情包含 `version`；本表的批量命令、第三方调用均要求幂等键。

| 模块 | 方法与路径 | 用途 |
| --- | --- | --- |
| 身份 | `POST /auth/login`、`POST /auth/refresh`、`POST /auth/logout` | 登录、令牌刷新与撤销，具体登录方式在工程阶段确定 |
| 当前用户 | `GET /me`、`PATCH /me/profile`、`GET /me/defaults`、`PATCH /me/defaults` | 用户、经纪人资料、默认配置 |
| 工厂草稿 | `GET/PUT /me/studio-draft?deviceId=...` | 按用户与已绑定设备保存完整配置、`version` 和 `savedAt`；PUT 带 `expectedVersion` 与幂等键 |
| 设备 | `POST /devices/register`、`GET /devices`、`POST /devices/:id/unbind` | 设备登记、列表和解绑 |
| 能力 | `GET /capabilities`、`GET /platform-accounts` | 可用导入方式、批量上限、模式、平台草稿/发布/查询能力与账号状态 |
| 平台绑定 | `POST /platform-accounts`、`POST /platform-accounts/:id/unbind` | 首次登录前创建 accountId 与设备绑定；解绑同时撤销本地会话使用权 |
| 房源 | `GET/POST /properties`、`GET /properties/:id`、`PATCH /properties/:id`、`POST /properties/:id/archive` | 搜索、人工创建、详情、编辑、归档；支持 `publishStatus=all/published/unpublished` |
| 全选 | `GET /properties/selection-ids` | 按筛选条件返回同一查询快照下的 ID、数量及上限；超限明确报错 |
| 导入 | `POST /property-imports`、`GET /property-imports/:id`、`POST /property-imports/:id/retry` | 提交编号或导入文件引用、查看逐条结果、重试指定失败项 |
| 素材 | `POST /assets/upload-intents`、`POST /assets/:id/complete`、`POST /assets/:id/download-url` | 获取短期上传地址、完成校验、按权限下载 |
| 本地素材 | `POST /assets/local-registrations`；`POST /properties/:id/assets`、`DELETE /properties/:id/assets/:assetId` | 登记设备文件、添加和移除房源素材关联；移除不删除历史引用 |
| 资源 | `GET /resources`、`GET /resources/:id/versions/:version`、`POST /resources/:id/versions/:version/download-intent` | 目录、版本清单、授权下载 |
| 声音与形象 | `GET/POST /voices`、`GET/POST /avatars`；各自详情、更新与删除端点 | 创建异步处理记录、试听及资料管理；删除需检查引用 |
| 批次 | `POST /production-batches`、`GET /production-batches`、`GET /production-batches/:id` | 原子创建批次及子任务、汇总查询 |
| 生产 | `GET /production-tasks`、`GET /production-tasks/:id`、`POST /production-tasks/:id/retry`、`POST /production-tasks/:id/cancel` | 查询、按允许阶段恢复、取消 |
| 历史成果 | `GET /production-tasks/:id/revisions/:revision` | 发布详情按绑定修订读取原文、配置与产物，不读取被重生覆盖的当前值 |
| 文案 | `PATCH /production-tasks/:id/script`、`POST /production-tasks/:id/script/regenerate`、`POST /production-tasks/:id/script/approve` | 修改、重生和按修订审核 |
| 发布 | `POST /publish-tasks`、`GET /publish-tasks`、`GET /publish-tasks/:id`、`POST /publish-tasks/:id/reconcile` | 按平台账号分别建任务、查询及核实未知结果 |
| 获客 | `GET/POST /lead-analysis-jobs`、`GET /lead-analysis-jobs/:id`、`GET /leads`、`GET/PATCH /leads/:id` | 分析任务列表与创建、查看线索和更新跟进状态 |
| 跟进 | `POST /leads/:id/suggest-reply`、`GET/POST /leads/:id/followups` | 生成建议、查看及追加记录；生成建议不触发发送 |
| 管理 | `/admin/users`、`/admin/devices`、`/admin/resources`、`/admin/ai-config`、`/admin/tasks`、`/admin/releases`、`/admin/remote-config` | 分别按需提供查询和管理命令，鉴权及审计独立于客户端 |

管理后台发布资源、发布客户端版本、修改供应商密钥采用独立命令与审计记录。密钥提交后只返回已配置状态和脱敏标识，不允许通过读取配置接口取回明文。

草稿云端持久化，SQLite 保存同归属镜像；首次无草稿时才加载用户默认配置，默认值不能覆盖已有草稿。断网修改恢复后通过版本比较保存，冲突不静默覆盖；账号切换严格隔离草稿与镜像，Mock 保持同形接口。全选接口支持搜索及发布分类快照，避免逐页遍历期间结果变动；创建批次时仍逐条重新校验归属和可用性。

设备执行接口另用设备身份鉴权：`POST /devices/:id/heartbeat`、`POST /devices/:id/executions/claim`、`POST /devices/:id/executions/:executionId/renew`、`POST /devices/:id/executions/:executionId/report`、`POST /devices/:id/executions/reconcile`。claim 由服务端分配允许执行的阶段，返回 `executionId / taskId / attempt / productionRevision / leaseToken / leaseExpiresAt`；renew、report 必须携带这些执行凭据。设备只报告阶段事实和产物引用，云端验证设备归属、租约、修订及当前状态后推进业务状态，不能接受任意状态覆盖。

### 文案审核

```http
POST /v1/production-tasks/task_a/script/approve
Idempotency-Key: task-a-approve-03
```

```json
{"expectedVersion": 8, "scriptRevision": 3}
```

响应为 `{"taskId":"task_a","version":9,"status":"queued","stage":"tts","approvedRevision":3}`。若审核期间文案已变化，返回 409 并要求刷新，不能批准用户未看过的新文案。

## 6. 错误与幂等

统一错误格式：

```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "文案已更新，请刷新后重新审核",
    "retryable": false,
    "fieldErrors": {},
    "requestId": "req_01"
  }
}
```

HTTP 使用 400 格式错误、401 未认证、403 无权限、404 不存在或不可见、409 状态/版本/幂等冲突、422 字段或能力校验失败、429 限流、5xx 服务异常。日志保留内部详情，响应不暴露堆栈、Cookie 或签名 URL。

`Idempotency-Key` 按用户与命令作用域保存请求摘要和结果。相同键与相同内容返回第一次结果；内容不同返回 409。客户端因网络不确定重试时沿用原键，用户明确新建时生成新键。数据库约束兜底，前端按钮禁用不构成幂等保障。幂等结果至少保留到对应操作结束并覆盖重试窗口；清理策略必须与客户端重试期限一同确定。

外部调用还需记录供应商请求引用和当前阶段尝试编号；幂等建任务不等于外部平台天然幂等。出现结果未知时，先核实已有结果，再决定是否重新执行。

异步调用先建立 ProviderOperation，再由适配器提交、轮询或接收验签回调；按供应商事件 ID 去重并检查签名时间窗防重放。回调必须匹配目标、修订和有效尝试，旧结果只留审计，不推进当前任务。供应商成功状态还需业务校验和产物登记，不能直接当作任务成功。

## 7. 上传和资源下载

上传意图先验证类型、用途和大小，绑定用户与对象键。完成接口由后端核查对象存在、实际大小、类型与哈希，必要时执行媒体探测；未通过校验的 Asset 不能进入生产任务。文件名、 MIME 和客户端声明都不是可信依据。

本地素材登记提交 `deviceId / localReference / mimeType / sizeBytes / sha256 / probe`，仅绑定且有效的设备可登记；`localReference` 是不透明令牌，本地路径不上云。云端记录设备可用性及探测结果，本地执行前再次核查实际文件与哈希，不能将声明直接当成云端已验证字节。

资源下载意图返回短期 URL、可信清单、签名、包哈希、大小与兼容条件。Sidecar 检查可信签名及内容哈希，限制解压路径和展开大小，在临时目录验证成功后原子安装。云端 `published` 与设备 `installed` 分开，设备上报安装版本和结果，不修改全局资源版本。任务使用的旧版本仍被引用时不得清除。

## 8. 本地 IPC 与执行通信

Renderer 只通过 Preload 暴露的白名单方法访问本地能力：`selectImportFile()`、`selectMediaFiles()`、`getExecutorStatus()`、`getResourceInstallations()`、`installResource(ref)`、`openPlatformLogin(accountId)`、`checkPlatformAccount(accountId)`、`logoutPlatformAccount(accountId)`、`subscribeLocalEvents(callback)`。平台登录前先创建绑定记录，校验 accountId 属于当前用户和设备。返回文件令牌和必要元数据，由主进程验证发送窗口、参数、文件范围与用途；不暴露通用 `exec`、任意文件读取或任意 IPC 通道。

Electron Main 与 Go Sidecar 使用 stdio 上的逐行 JSON-RPC 消息，所有协议输出进入 stdout，诊断日志进入 stderr。最小请求和事件：

```jsonl
{"jsonrpc":"2.0","id":"rpc_01","method":"resource.install","params":{"id":"video_01","version":"1"}}
{"jsonrpc":"2.0","id":"rpc_01","result":{"localJobId":"local_01"}}
{"jsonrpc":"2.0","method":"job.updated","params":{"localJobId":"local_01","status":"running"}}
```

RPC 返回受理不等于执行完成；结果通过事件及查询核实。主进程设置超时、最大消息长度、方法白名单和错误映射，不开放无鉴权本地 HTTP。平台 Worker 只接收经验证的账号引用、受控文件引用和命令，平台会话保存在本地受保护目录；Worker 向 Go 回报状态，由云端记录业务结果。

## 9. 云端事件与断线恢复

WSS 事件至少包含：

```json
{
  "eventId": "evt_01",
  "seq": 105,
  "type": "production_task.updated",
  "entityId": "task_a",
  "entityVersion": 9,
  "occurredAt": "2026-10-30T09:00:00Z",
  "payload": {"status":"queued","stage":"tts"}
}
```

`seq` 是每用户事件流的递增序号，用于发现缺口，不作为跨用户全局顺序。前端按 `eventId` 去重、按 `entityVersion` 丢弃旧更新；收到通知后使相应 Query 失效并查询详情。连接恢复时先尝试从最后序号补发；服务端超出保留窗口则明确返回需要全量同步，客户端重查活动任务、发布任务及资源安装状态。

云端 PostgreSQL 是业务状态来源；SQLite 保存设备执行日志、检查点和待同步结果，不能在断网时擅自覆盖云端新版本。设备结果携带 `taskId / attempt / productionRevision / leaseToken / entityVersion`，服务端拒绝失效租约、旧尝试和旧修订；重连后先对账再继续。事件只是通知，接口查询和执行日志共同保证应用重启后仍能还原状态。

共享 TypeScript DTO 放 `packages/shared-types`，请求封装放 `packages/api-client`，资源清单及验证定义放 `packages/resource-schema`。Go 按同一契约编写边界校验；Mock 必须遵守相同状态、错误和幂等语义，不能以本地演示绕过真实版本冲突。

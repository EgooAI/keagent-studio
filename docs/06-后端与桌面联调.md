所有真实 AI 请求仅在 Go 云端发出。网页和 Electron 不持有供应商密钥。两端业务请求直连 Go `/v1/*`；认证请求保留 `/api/auth/*`。Go 当前仍监听回环地址。未来可以将认证与业务路径分别转发到两个服务，本次不增加域名、Caddy、Nginx 或 Docker。

与规划的差异：未复制 SDK 的整套商业后台或迁移现有后台到 Next.js；复用 SDK 认证、Admin 和审计客户端，Next.js 作为服务端。套餐、积分、支付、工单、营销归因和通用生成执行器未注册。

## 本机启动

Node.js 24、pnpm 10、Go 1.25+、PostgreSQL 18。SDK 的完整分发包已复制到 `vendor/auth-sdk.tgz`，固定在锁文件中；不用依赖另一仓库的工作区链接。

1. 复制 `.env.example` 为 `.env.local`，填写独立数据库和随机服务端密钥。
2. 建立数据库，运行 `pnpm setup:auth` 显式迁移 SDK 并初始化管理员。已有环境也需再执行一次以增量创建 `jwks` 表；不重建用户表，不改变用户 ID，已有管理员不会被覆盖密码或提升权限。
3. `pnpm dev:backend` 启动 Next.js 和 Go，或分别运行 `pnpm dev:control`、`pnpm dev:cloud` 调试。首次启动 Go 创建本项目业务表。
4. 分别运行 `pnpm dev:admin`、`pnpm dev:desktop`。若 5173 已有预览服务，先关闭该服务。

当前开发机已在 `output/postgres` 初始化独立集群，并使用随机密码。启动命令：

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe' -D output\postgres -l output\postgres.log -o '-h 127.0.0.1 -p 55432' start
```

本机管理员邮箱和初始密码见不入库的 `.env.local` 的 `BOOTSTRAP_ADMIN_EMAIL`、`BOOTSTRAP_ADMIN_PASSWORD`。只用于本地联调，不作为部署凭据。公开注册关闭，后台可以创建普通账号；SMTP、用户自助重置密码和管理员 MFA 尚未接入，不能按生产身份系统交付。

## 身份与设备

SDK 是账号与会话权威，保留现有登录和管理员配置，公开注册仍关闭，未额外开启 OAuth。网页使用 HttpOnly Session Cookie，Main 使用 SDK 的签名 Bearer Session 调用 `GET /api/auth/token` 换取 5 分钟 Access Token；Go 仅接受 JWT，不接受原始 Session 凭据。

SDK 使用 Ed25519 签名，JWT 仅包含 `sub`（现有用户 ID）、`sid`、`iss`、`aud`、`iat`、`exp`。私钥保存在 SDK 的 PostgreSQL JWKS 表且默认加密；`GET /api/auth/jwks` 只返回公钥。自动轮换间隔 30 天，旧钥保留 10 分钟。Go 固定 EdDSA，校验签名与声明，公钥缓存 5 分钟，未知 kid 受 5 秒刷新冷却限制。刷新失败不接受过期缓存；已有未过期公钥仍可验证对应 Token。

签名验证由 Go 独立完成，随后 Go 每请求直接联查 PostgreSQL 的 Session / user，确认会话对应、未过期、用户未封禁，并读取当前角色。封禁、退出、撤销 Session 和角色变更在提交后的下一次请求生效，无需等待 JWT 过期。数据库不可用返回 503，不放行。这一阶段减少了 HTTP 转发和 SDK 开销，仍保留实时状态查询成本；未增加 Redis。

Electron 在工作区加载前验证身份，每 15 秒通过 Go `/v1/session` 复核会话并登记设备心跳。SDK Session 凭据在 Main 使用系统加密持久化；JWT 仅在 Main 内存，IPC 不提供 Token 读取能力。浏览器 JWT 仅在内存，业务请求使用 Bearer 且不携带 Cookie。两端在第 270 秒后按需续取，合并并发换取；401 最多续取并重试一次，403、服务错误和网络错误不重放业务操作。退出或换账号清理 JWT 并丢弃旧异步响应。

设备标识按安装与用户稳定生成，不能作为独立登录凭证。换账号清空 Query 缓存；真实数据不从 Mock localStorage 导入。系统凭据保护不可用时拒绝保存登录。

设备解绑后拒绝该设备后续请求；用户封禁、撤销会话后拒绝后续请求。尚无 Go Sidecar、平台 Worker 或执行租约，因此本轮没有本地领取任务。已发送供应商请求不能因退出而撤回。

## 直连配置与迁移

`.env.example` 已包含以下配置，现有 `.env.local` 未填写新增项时使用本机默认值：

| 配置 | 默认 / 用途 |
| --- | --- |
| `VITE_AUTH_API_URL` | 空：网页同源 `/api`，开发由 Vite 转发到 18080；可设置认证服务绝对地址 |
| `VITE_GO_API_URL` | `http://127.0.0.1:18081`，浏览器直连 Go，变更后重启 Vite / 重新构建 |
| `CONTROL_API_URL` | Electron Main 的认证地址，默认 `http://127.0.0.1:18080` |
| `GO_API_URL` | Main 业务地址及旧代理上游，默认 `http://127.0.0.1:18081` |
| `JWT_ISSUER` | 默认 `BETTER_AUTH_URL`，未配置时 `http://127.0.0.1:18080`；两服务必须一致 |
| `JWT_AUDIENCE` | 默认 `keagent-api`；两服务必须一致 |
| `JWKS_URL` | 默认 `BETTER_AUTH_URL` 加 `/api/auth/jwks`；仅固定配置来源，外部地址必须 HTTPS |
| `TRUSTED_ORIGINS` | 默认 `http://127.0.0.1:5174,http://127.0.0.1:5173`，认证与 Go 共用精确来源列表 |
| `ALLOW_LEGACY_GATEWAY` | 默认兼容开启；两服务均设 `false` 后关闭旧签名路径 |

本地统一使用同一种主机名；`localhost` 与 `127.0.0.1` 的 Cookie、Origin、issuer 不可混用，若使用 localhost 需同步修改相关配置和允许来源。Go 业务 CORS 不启用 Cookie 凭据，仅接受允许来源及 Authorization / Content-Type / X-Keagent-Device 预检；认证跨域保留 Cookie 凭据和 SDK 自身 CSRF 校验。

迁移顺序：先执行认证增量迁移，部署支持 JWT 的认证与 Go，再升级客户端。旧客户端仍可通过 Next.js `/v1/*` 使用 Session + HMAC；JWT 请求失败不会回退旧方式。确认旧客户端迁移完成后，两服务设置 `ALLOW_LEGACY_GATEWAY=false` 并重启，此时可以移除 `INTERNAL_API_SECRET`。关闭后旧 Next.js 入口返回 410，Go 拒绝 HMAC 身份。

如需回退客户端版本，先恢复两服务的兼容开关和原内部密钥，再运行旧客户端；无需删除 JWKS 表或回滚账号数据。拥有有效 JWT 和新鲜公钥缓存的 Go 不依赖 Next.js 处理业务，但登录、Token 续取及公钥刷新仍需要认证服务，实时账号状态仍依赖 PostgreSQL。

## 当前业务能力

- 用户：SDK 登录、管理员开户、封禁/启用、撤销会话、身份审计。
- 设备：登记、心跳、后台查询、解绑；云端复核归属与会话。
- 工作区：按用户存储，支持人工房源录入、修改、用户资料与配置草稿保存。
- 公共资源：管理员创建与上下架、客户端读取同一目录。已发布内容不可修改，后台变更与业务审计在同一事务保存。目前仅资源元数据，没有资源包上传、签名和本地安装。
- 批次：校验房源归属、重复房源和已发布资源版本，创建独立任务，按用户和请求键幂等；同键不同内容拒绝。
- 文案：数据库持久化任务，单 Go Worker 调用 OpenAI 兼容 `/chat/completions`，保存文案与审核状态；账号封禁后不发起新的调用。关闭审核时文案后明确停在未配置的 TTS 阶段。
- AI 后台：只展示服务端配置状态、模型与接口地址，不返回密钥。当前密钥和模型由服务端环境配置，不提供浏览器编辑密钥接口。

第一轮业务记录使用 PostgreSQL 用户级 JSONB 文档并加行锁；这是联调阶段的实现，增加业务检索、报表和更高并发前需按第 04 章迁移为独立实体表。内部命令桥 `/v1/commands/:name` 有固定命令分支，未支持的命令返回 501，不执行 Mock；正式 REST 端点仍待逐步替换。

## 云端 AI

配置 `AI_BASE_URL`（按供应商提供的兼容地址）、`AI_MODEL`、`AI_API_KEY` 和 `AI_ALLOWED_HOSTS`。接口必须 HTTPS，域名必须在服务端允许列表；拒绝私有地址、回环地址与重定向。请求超时或不确定结果停止自动重试，不伪造成功。AI 只获得任务房源快照。

现有文案实现使用固定的房产口播系统提示词；后台提示词资源的自定义正文路由尚未接入。服务崩溃时正在请求的任务保留“结果未知”诊断，需人工核查，尚无供应商任务查询适配器。

TTS、声音克隆、数字人、评论分析、房源号自动抓取、对象存储、FFmpeg、Sidecar、平台授权与发布、安装包分发、远程开关尚未接通。相关真实命令返回明确错误。没有配置供应商时只能验证未配置路径，不能称为真实 AI 成片验收通过。

# 开发计划与验收

本章把首版划分为可独立检查的交付阶段。先用 Mock 验证完整交互，再逐段替换真实 Go 服务、AI 和本地执行器，最后完成真实安装包验收。这里的阶段是实施顺序，不代表已经完成，也不预设工期。

## 1 开发前的能力验证

在页面开发并行开展以下小范围验证，尽早暴露会影响交付的外部限制。

| 验证 | 最小产出 | 不通过时的处理 |
| --- | --- | --- |
| 房源获取 | 合法来源的一套房源资料和素材，或可用授权接口说明 | 使用文件和人工导入，不虚构自动获取能力 |
| TTS 和声音克隆 | 本人授权样本、试听、异步状态和失败结果 | 采用可用预设音色，克隆能力标注未接入 |
| 数字人 | 一段本人形象开场，确认音画输入、费用及生成耗时 | 继续交付纯口播；露脸模式保持不可用提示，不能算全量验收通过 |
| 平台草稿 | 每个平台一次已授权账号操作和结果核对 | 提供文件包和人工操作，不标为平台草稿成功 |
| 本地运行时 | 三类目标安装包至少可找到并启动 Sidecar、FFmpeg、浏览器 Worker | 修复构建链后再开展安装包功能验收 |

AI 密钥只在服务端使用。验证记录应保留接口示例、服务限制、失败处理、授权条件和测试环境，不保存明文用户凭据。

## 2 阶段与完成条件

| 阶段 | 主要工作 | 可检查的完成条件 |
| --- | --- | --- |
| M0 工程与契约 | Monorepo、桌面壳、后台壳、共享类型、格式与检查脚本、Mock fixtures | 桌面和后台能启动；类型检查通过；环境样例不含密钥；核心接口有示例 |
| M1 核心 Mock 闭环 | 房源导入、房源多选、视频配置、批次、审核、成果与平台独立任务 | 一次选择三套房源可创建三条任务；审核后继续；失败可定位；刷新保留草稿 |
| M2 其余页面与后台 | 工作台、获客、设置、资源下载、后台资源与 AI 配置、错误和空态 | 六导航完整可交互；管理后台可发布模拟资源；客户端可发现对应版本 |
| M3 云端真实业务 | 鉴权、用户隔离、PG 迁移、房源、任务、资源、对象存储、事件同步 | 跨用户访问拒绝；重复请求不重复写入；断线可补账；后台权限正确 |
| M4 AI 与本地生产 | 真实文案与 TTS、授权声音/形象、Sidecar、FFmpeg、资源安装、恢复与回传 | 用户提供一套真实素材可完成两种模式；审核修订和资源版本正确；可恢复失败 |
| M5 真实平台与获客 | 已验证的账号连接、草稿或人工完成流程、结果核对、评论分析 | 两个平台各有实际能力说明和测试记录；未知结果不会重复提交；分析可追溯到评论 |
| M6 正式交付 | 签名、公证、更新、数据库备份恢复、安装卸载、性能和回归 | 目标系统实机通过；正式环境无模拟成功；交付安装包、配置说明和已知限制 |

实现约定：前端与后台可在 M0 后共享类型并行开发；真实能力验证从 M0 开始，不等 M4 才确认供应商或平台限制。没有完成 M3 至 M6 时，只能交付前端原型或内测版本，不能宣称整个平台已完成。

## 3 工作分工和依赖

| 工作面 | 职责 | 依赖 |
| --- | --- | --- |
| 产品与界面 | 固定交互、错误文案、状态映射、默认配置 | 产品范围与页面规范 |
| 桌面前端 | 六导航、表单、选择器、批次与详情、Mock、IPC 调用 | 共享契约与桌面壳 |
| 管理后台 | 用户设备、资源版本、AI 配置、任务诊断、客户端版本 | 管理员权限及云端 API |
| 云端 Go | 鉴权、持久化、调度、AI Provider、对象存储、事件和审计 | 数据模型、外部供应商 |
| 本地 Go 与 Worker | 资源下载、执行恢复、FFmpeg、平台会话、打包运行时 | IPC、任务领取和平台能力验证 |
| 测试与交付 | 业务回归、隔离测试、平台实测、安装包与恢复测试 | 每阶段可运行产物 |

接口先以共享类型和请求响应样例固定。接口变化必须同时更新 Mock、真实实现、调用页面和关键测试，不保留两个互不兼容的“临时接口”。

## 4 开发环境与命令约定

前端工程已提供以下 JS 启动、构建和检查脚本；Go 服务仍属于后续实施范围。具体本地使用说明以根 README 为准。

| 预期命令 | 用途 |
| --- | --- |
| `pnpm install` | 按锁文件安装 JS 工作区依赖 |
| `pnpm dev:desktop` | 开发桌面客户端，默认使用明确标识的 Mock 模式 |
| `pnpm dev:admin` | 开发独立管理后台 |
| `pnpm typecheck` | 工作区 TypeScript 检查 |
| `pnpm lint` | 工作区静态检查 |
| `pnpm test` | 前端核心逻辑和契约测试 |
| `pnpm test:e2e` | 完整 Mock 业务流程回归 |
| `pnpm build` | 构建桌面前端、后台及 Worker |
| `pnpm package:desktop` | 构建当前系统未签名的 Electron 前端目录；完整执行环境和正式安装包在后续接入 |
| `go test ./...` | 分别在 `services/cloud` 和 `services/local-agent` 中执行 Go 测试 |

开发工具版本在 M0 按已验证兼容组合锁定，提交锁文件与 `.env.example`，不要把“latest”作为可复现的构建配置。Go 迁移和本地服务启动命令在真实实现选型后补到根 README。

前端仅配置 API 地址和 Mock 开关；模型凭据、数据库密码、对象存储密钥、资源签名私钥和平台凭据不能进入前端环境变量。演示环境、测试环境、生产环境使用不同数据和存储范围。

## 5 验收场景

每条记录应包含环境、操作、预期、实际结果和缺陷链接。表中“自动”表示建议加入自动化回归，“实机”表示需要在正式目标环境验证。

| 编号 | 场景 | 预期 | 检查方式 |
| --- | --- | --- | --- |
| A01 | 导入空行、重复号和失败号 | 去空去重，逐项结果准确，失败项可单独重试 | 自动 |
| A02 | 上传有效及格式错误的 CSV 或 Excel | 识别房源号列，格式错误可定位，不能导致客户端崩溃 | 自动与人工 |
| A03 | 多选后切 Tab、搜索、分页、取消并重开 | 已确认值保留；取消不提交临时选择 | 自动 |
| A04 | 房源只有生成视频或平台草稿 | 仍在未发布过；正式发布核对成功后转入已发布过 | 自动 |
| A05 | 选择三套房源创建任务并重复提交 | 一个批次三条独立任务；同一幂等键不生成重复批次 | 自动 |
| A06 | 纯口播切换露脸且没有形象 | 通用配置保留；露脸提交被就近提示拦截 | 自动 |
| A07 | 开启审核，修改并批准文案 | 审核前不执行 TTS；批准修订与下游内容一致 | 自动与真实链路 |
| A08 | 下游已生成后修改文案 | 旧下游标记失效，不误用旧成片，新的修订可重新生产 | 自动 |
| A09 | 批次一条失败、其他任务完成 | 可独立重试失败项；批次汇总与子任务一致 | 自动 |
| A10 | 同一成片创建两平台任务，一条失败 | 各平台标题、账号和状态独立，另一条不受影响 | 自动 |
| A11 | 平台提交后超时或客户端崩溃 | 显示待确认；查询或人工核对后再允许确定的下一步 | 自动与平台实测 |
| A12 | 生成任务后更新或下架模板 | 历史任务保留原版本；新任务不能选择已下架版本 | 自动 |
| A13 | 下载中断、哈希错误、签名错误、越界压缩路径 | 不注册半成品，不切换当前可用资源，不写出缓存目录 | 自动 |
| A14 | 断网、重连、重复和乱序事件 | 以 REST 快照和实体版本校准，不倒退状态、不重复执行 | 自动 |
| A15 | 进程重启、租约过期、旧设备迟到回报 | 可恢复；旧租约不能覆盖新执行；外部副作用先核对 | 集成 |
| A16 | 用户 A 访问用户 B 的对象或签名下载地址 | API 对跨用户对象拒绝；不生成越权下载凭证 | 自动 |
| A17 | 获客评论没有预算或区域 | 显示未识别，保留原文，话术可编辑，跟进记录可保存 | 自动与人工 |
| A18 | 设置修改默认声音、形象或模板 | 新配置生效，既有任务快照不变化；声音和形象独立 | 自动 |
| A19 | 后台资源发布和用户禁用 | 资源按兼容性出现；被禁用用户新请求拒绝并撤销有效会话 | 集成 |
| A20 | 1280×800、1440×900 和键盘操作 | 表单可读，弹窗按钮可达，焦点和 Escape 正确，无遮挡 | 人工与界面回归 |
| A21 | 无开发工具的目标系统安装 | 内置执行环境可用；中文和空格路径可用；卸载不误删用户数据 | 实机 |
| A22 | 升级客户端或运行时失败 | 用户任务与缓存保留，失败恢复可用版本，数据库迁移不丢数据 | 实机与集成 |
| A23 | 实际两种模式生成和视频播放 | 音画、字幕时序、封面和导出规格正确，无空白片段 | 实机与人工 |
| A24 | 数据库及对象存储恢复演练 | 可恢复业务引用、有效成果和资源版本，孤立文件可诊断 | 运维演练 |
| A25 | 本地素材只登记元数据、不上传原视频 | 绑定设备可生产；其他设备提示素材不在本机，不泄露本地路径 | 集成与实机 |
| A26 | 本地渲染在断网后完成、租约已到期 | 先对账再授执行权；可验证成果被复用，不直接接纳旧租约状态 | 集成 |
| A27 | 文案修订或取消任务后供应商回调到达 | 旧修订结果仅保留历史，不推进新修订或复活取消任务 | 集成 |

测试优先覆盖状态转换、审核、幂等、资源校验、权限隔离和外部副作用恢复。不要通过大量测试装饰性 JSX 替代核心业务验证。页面截图检查可以辅助视觉验收，不能替代真实点击和安装包测试。

## 6 运行指标与故障诊断

云端日志关联 `request_id`、用户、设备、批次、任务、执行尝试和资源版本。记录阶段开始、结束、错误码、供应商请求标识及耗时；日志中不写完整平台会话、访问令牌、模型密钥和未经必要处理的个人资料。

首版监控任务积压、阶段耗时、成功与失败数量、待审核时长、设备在线、租约过期、资源下载失败和平台待确认数量。吞吐和批量上限以目标设备测量后确定，不在文档里承诺无依据的并发量或完成时间。

用户可导出经过脱敏的诊断包。管理员只能看到已授权的诊断信息；需要查看完整素材时应有业务权限和审计记录。

## 7 正式发布与维护

1. 完成数据库迁移备份和恢复验证，再执行向前迁移；不能仅靠回滚应用二进制撤销不兼容的数据变更。
2. 发布 Go 服务和后台，验证鉴权、对象存储、资源签名、任务领取与事件通知。
3. 在测试设备使用目标安装包执行实际房源到成片流程，核对版本、运行时和平台能力。
4. 发布签名安装包及校验信息，先小范围验证；更新清单与资源清单分别管理。
5. 通过远程开关停用故障供应商或平台能力；保留本地成果和人工完成路径。
6. 故障恢复优先停止重复副作用，核对供应商或平台结果，再恢复任务执行。

交付时必须包含安装包、版本与兼容矩阵、启动与部署说明、迁移说明、测试结果、供应商与平台接入状态、备份恢复说明和已知限制。发布说明应明确哪些是实际接入、哪些是模拟、哪些需要用户手工完成。

## 8 Agent 执行约定

开发 Agent 先阅读根 README 及对应章节，再按 M0 至 M6 实施。每次交付一个可运行的阶段，修复本阶段已经影响的调用方、Mock 和测试，不擅自增加新一级导航或收费功能。

任何“完成”的报告都应带启动方式、变更范围、实际运行的检查结果和剩余未接入能力。外部平台不可用时提交可复现的限制和已经完成的替代路径，不把配置按钮或模拟成功当作真实集成完成。

# 16 积分售卖与计费设计

整理日期：2026-11-11。状态：设计定稿，待实施。

## 已确认的决策

- 售卖方式：兑换码 + 后台手动充值（第一期不做在线支付）。
- 计费主体：按账号（`owner_id`，即登录用户）计，不做机构共享池。
- 积分分两类：
  - **充值积分**（purchased）：兑换码兑换、后台手动充值所得，**不过期**。
  - **赠送积分**（granted）：新用户欢迎赠送、后台手动赠送所得，**会过期**（有效期在发放时指定）。
- 新用户默认**不送**积分；后台可配置是否自动赠送及额度（开关 + 数额 + 有效期天数）。
- 单价在管理后台可配置，改价不影响已冻结的扣费。

## 收费操作清单

只对"真正调用供应商、产生成本"的云端操作收费；查询、命中缓存、本地合成、抖音发布不收费。`script-vision`（看图写文案）与 `script`（按模板改写）按同一项 `script` 计费。

| 计费键 | 触发接口 | 计费方式 | 建议默认单价 |
| --- | --- | --- | --- |
| `opening` | `POST /v1/panorama/opening-submit` | 按次（异步，成功才结算） | 100 |
| `voice_clone` | `POST /v1/voices/create` | 按次（一次性） | 200 |
| `script` | `POST /v1/panorama/script-vision`、`POST /v1/panorama/script` | 按次（含重新生成） | 5 |
| `tts` | `POST /v1/panorama/tts` | 按千字符（预估冻结，按实际结算） | 10 / 千字 |

AI 扩图（`image_expand`）已下线。历史账单仍可查询，只有所选日期内实际结算过的扩图消耗才会列入服务消耗汇总。

不收费：`*-query`、`capabilities`、`template`、`beike-import`、资源/工作区读写、抖音全部接口、成片交接、本地渲染。单价为 0 的操作跳过扣费，不产生流水。

## 数据模型

新增三张表 + 一张兑换码表，拼入 `main.go` 的 `schema`（与 `aiSettingsSchema` 同样的方式）。余额不放入 `keagent_workspace` 的 jsonb（整体重写、并发覆盖、无法对账）。

```sql
-- 积分批次（lot）：每一笔发放都是一个批次
CREATE TABLE IF NOT EXISTS keagent_credit_lot (
  id text PRIMARY KEY,
  owner_id text NOT NULL,
  kind text NOT NULL,               -- purchased | granted
  initial_amount bigint NOT NULL,
  remaining bigint NOT NULL CHECK (remaining >= 0),
  held bigint NOT NULL DEFAULT 0 CHECK (held >= 0),
  expires_at timestamptz,           -- purchased 恒为 NULL
  source text NOT NULL,             -- welcome | admin_grant | code | order
  source_ref text NOT NULL DEFAULT '',
  created_at timestamptz NOT NULL DEFAULT now());
CREATE INDEX IF NOT EXISTS keagent_credit_lot_owner_idx ON keagent_credit_lot(owner_id);

-- 扣费单（hold）：一次待结算的扣费
CREATE TABLE IF NOT EXISTS keagent_credit_hold (
  id text PRIMARY KEY,
  owner_id text NOT NULL,
  op text NOT NULL,                 -- opening | voice_clone | script | tts | image_expand
  ref_id text NOT NULL DEFAULT '',  -- 任务/请求关联 ID
  amount bigint NOT NULL,
  state text NOT NULL,              -- held | captured | released
  allocation jsonb NOT NULL,        -- [{lot_id, amount}] 冻结时的批次分配
  idem_key text NOT NULL,
  price_version text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  settled_at timestamptz,
  UNIQUE (owner_id, op, idem_key));

-- 流水：只追加
CREATE TABLE IF NOT EXISTS keagent_credit_ledger (
  id text PRIMARY KEY,
  owner_id text NOT NULL,
  kind text NOT NULL,               -- grant | hold | capture | release | redeem | adjust | expire
  lot_id text NOT NULL DEFAULT '',
  amount bigint NOT NULL,           -- 正负号表示增减
  op text NOT NULL DEFAULT '',
  ref_id text NOT NULL DEFAULT '',
  idem_key text NOT NULL DEFAULT '',
  price_version text NOT NULL DEFAULT '',
  operator_id text NOT NULL DEFAULT '',
  metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at timestamptz NOT NULL DEFAULT now());

-- 兑换码：只存哈希
CREATE TABLE IF NOT EXISTS keagent_credit_code (
  batch_id text NOT NULL,
  code_hash text PRIMARY KEY,       -- sha256(规范化后的码)
  amount bigint NOT NULL,
  used_by text NOT NULL DEFAULT '',
  used_at timestamptz,
  expires_at timestamptz,           -- 兑换截止时间
  note text NOT NULL DEFAULT '',
  created_at timestamptz NOT NULL DEFAULT now());
```

价格与新用户赠送配置存 `keagent_setting`：

- id `credit_pricing`：`{"version": 1, "prices": {"opening": 100, "voice_clone": 200, "script": 5, "tts_per_kilo_char": 10, "image_expand": 0}}`
- id `credit_welcome`：`{"enabled": false, "amount": 0, "validityDays": 30}`

冻结时把 `price_version` 和单价快照进 `keagent_credit_hold.allocation` 同级的字段（或 metadata），结算按快照算，改价不影响在途单。

## 扣费流程

### 冻结（hold）

供应商调用前执行，单事务内完成：

1. 过期清扫（见下）。
2. `SELECT ... FOR UPDATE` 按排序取批次：**先扣赠送积分（expires_at 最近优先），再扣充值积分（created_at 最早优先）**，即"先花要过期的"。
3. 总余额不足时返回 `402`，错误码 `CREDITS_INSUFFICIENT`（`respond` 已支持 `ErrorCode()`），前端统一引导去兑换。
4. 写 `keagent_credit_hold`（allocation 记录每个批次扣了多少）+ `hold` 流水，同时更新各批次的 `remaining -= x, held += x`。
5. 幂等键复用现有机制：`opening` 用 `input_hash`，`voice_clone` 用 `request_key`，`image_expand` 用 `request_key`，`script` / `tts` 用任务 ID + 修订号。同一幂等键重复请求直接返回已有 hold，不重复扣。

### 结算（capture）与释放（release）

- 同步接口（`script`、`tts`）：供应商返回成功当场 capture；失败当场 release。
- `opening`：`opening-query` 收到 `succeeded` 时 capture；`failed` / `cancelled` 时 release。
- `tts` 实际用量与预估不同：按实际字符数 capture，差额 release 回原批次。
- 供应商失败但**结果未知**（沿用现有"请先核查供应商结果"语义）：保持 held，不自动释放，由后台对账处理（管理后台可人工 capture / release），防止用户用重试刷掉在途扣费。
- 释放回原批次；若原**赠送**批次在冻结期间已过期（冻结中的积分本身不参与过期），退回金额转入充值积分池——扣费失败不是用户的错。

### 过期（expire）

- 后台清扫协程每分钟跑一次 + hold 前顺带执行：对 `held = 0` 且 `expires_at < now()` 的赠送批次清零 `remaining`，写 `expire` 流水（amount = 清零额）。冻结中的部分不参与过期。

## 发放入口

| 入口 | 积分类别 | 说明 |
| --- | --- | --- |
| 新用户欢迎赠送 | granted | 挂在 `workspacePayload` 首次播种（`INSERT ... ON CONFLICT DO NOTHING` 用 `RETURNING` 判断是否新账号）；读 `credit_welcome` 配置，关着就不送 |
| 后台手动充值 | purchased | `/v1/admin/credits/grant`，`kind=purchased`，必填备注，写 `keagent_audit` |
| 后台手动赠送 | granted | 同上，`kind=granted` + 有效期天数 |
| 兑换码 | purchased | `POST /v1/credits/redeem`，桌面端设置页输入；码 sha256 存储、一次性、可设兑换截止 |
| （二期）在线支付 | purchased | 订单表 + 回调验签，按订单号幂等 grant |

兑换码生成：`POST /v1/admin/credit-codes`（批量、前缀、面额、数量、截止时间），**明文码仅在创建响应里返回一次**，服务端只留哈希。

## 接口一览

用户侧（走现有网关签名与 JWT）：

- `GET /v1/credits`：余额总览（充值可用 / 赠送可用 + 最近过期时间 / 冻结中 / 最近流水）。
- `POST /v1/credits/redeem`：兑换码兑换。

管理后台（`/v1/admin/`，需 admin 角色）：

- `GET /v1/admin/credits/list`：按用户查余额汇总（带 `ownerId` 返回批次、冻结单与流水明细）。
- `GET /v1/admin/credits/holds`：在途冻结单列表（对账工作清单）。
- `POST /v1/admin/credits/grant`：手动充值 / 赠送（必填备注）。
- `POST /v1/admin/credits/adjust`：差错调整（正负均可，必填备注，写 audit）。
- `POST /v1/admin/credits/settle`：对账人工 capture / release 在途 hold。
- `GET/POST /v1/admin/credits/pricing`：单价配置（带版本号）。
- `GET/POST /v1/admin/credits/welcome`：新用户赠送配置。
- `POST /v1/admin/credit-codes`：生成兑换码批次（明文只返回一次）；`GET /v1/admin/credit-codes`：批次列表与使用情况。

## 桌面端与管理后台

- 桌面端：设置页显示余额与"去兑换"；视频工厂 `createBatch` 前按当前价目显示预估（仅预估，不在建批次时扣，实际扣在各调用点）；402 `CREDITS_INSUFFICIENT` 统一弹兑换引导。
- 管理后台：侧栏加"积分"页（用户余额、流水、手动充值/赠送、对账、价目与赠送配置、兑换码批次）。

## 并发与边界

- 所有余额变动在单事务内用条件更新保证原子（`remaining >= 扣减额` 不满足即不足）；hold 分配用 `FOR UPDATE` 锁批次行。
- 流水 `UNIQUE(owner_id, op, idem_key)` 兜底，任何路径不得绕过。
- 金额一律 `bigint` 整数积分，不用浮点。

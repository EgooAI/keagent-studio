# 贝壳房源素材输入核查

核查日期：2026-11-07。目标是先确认贝壳实际能够返回什么，再选择匹配的开发素材。本次找到了另一个贝壳官方接口的响应示例并下载其素材；尚未取得 AI 平台成功响应，不将两者的格式混用。后续开放平台接入及制作方式见 [房源素材制作说明](video-production-sources.md)。

## 当前结论

| 证据                                                                           | 核实结果                                                                                          | 可以采用的范围                                                           |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 用户指定的 `beike-ai-platform` 官方技能与 CLI                                  | 有房源详情、图片/户型图/VR 物料查询；七个历史买房技能发布版和 npm 发布包均未找到完整成功物料 JSON | 确认能力说明，不能确定全部响应字段或把 VR 链接当全景原图                 |
| [贝壳开放平台「图片验真」官方响应示例](https://open.ke.com/service/picVerify/) | `data.prospect` 按空间分组；另有 `frame`、`resblock` 等图片地址                                   | 原样保留此接口的示例及其真实可访问素材，不能声称是 AI 平台 material 响应 |
| 本次实际下载与图像解码                                                         | 官方示例中的 11 个图片地址全部下载成功，文件均可完整解码，合计 10,203,993 字节                    | 作为本地素材候选；无 VR、视频或已核验挂牌身份                            |

**选用候选为官方响应示例中的原始图片组。** 不把来源页面的请求示例地址、页面演示地址或其他房源的价格、面积拼接到这组图片上。只能确认这些 URL 出现在同一份官方示例中，不能凭这一点核实其产权身份或在售状态。

| 官方字段                | 数量 | 本地文件                                   | 实测尺寸                |
| ----------------------- | ---- | ------------------------------------------ | ----------------------- |

| `data.prospect.room`    | 3    | `bedroom-01.jpg` 至 `bedroom-03.jpg`       | 1440 × 1080             |

| `data.resblock.name`    | 3    | `community-01.jpg` 至 `community-03.jpg`   | 1440 × 956 / 810 / 1080 |

其余示例字段包括空的单元号、房号、楼栋号/外立面等图片数组，以及 `downLoad: null`。本示例没有 VR 或视频字段，不能据此推断其他贝壳接口也不提供。

运行：

```powershell
node scripts/prepare-beike-material-sample.mjs
```

输出位于 `output/property-samples/beike-official-pic-verify/`：11 张原始图片、`response.example.json`、逐图来源/字节数/SHA-256 的 `manifest.json` 和 `SOURCE.txt`。脚本只下载示例公开 URL，不请求鉴权接口；再次运行复用本地缓存。下载原图保留原水印，图片不提交到仓库。公开可访问不等于获得独立商业分发授权，本组先作本地开发参考。

该组是普通室内照片和户型图，不能直接喂给要求等距柱状全景的执行器。室内普通照片进入 AI 扩图路线；户型图与小区图不自动充当室内镜头。

## 目前能确认的调用边界

| 阶段     | 官方命令                                                     | 可确认的用途                                                                                                             |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 搜索房源 | `beike buy search -c <城市> -q <条件>`                       | 获取候选房源；详情和物料必须沿用搜索返回的真实实体 ID                                                                    |
| 房源详情 | `beike buy detail -c <城市> --id <ID> --entity-type house`   | CLI 帮助说明包括图片、房源描述等；技能说明要求展示价格、户型、面积、楼层、朝向、电梯、楼龄和交易属性，具体取决于返回内容 |
| 房源物料 | `beike buy material -c <城市> --id <ID> --entity-type house` | 独立物料查询；技能说明涵盖图片、户型图、VR，图片用于展示，VR/详情以链接呈现；缺失时不可补造                              |

最新 CLI 的物料命令支持多个 ID，实体类型为 `house`（默认，二手房）或 `newhouse`（新房），城市必填。默认输出单行 JSON，`--json` 输出格式化原始 JSON。这仅确认输出形式，不等于确认业务字段。

## 尚未确认，不能预设的内容

1. 成功响应的完整封装、字段名、层级、必填性、媒体类型枚举与错误格式。
2. 图片返回的是原图、缩略图、分组列表还是文字中的图片链接；是否带空间名称和稳定图片 ID。
3. 户型图是否独立分类，是否有对应户型或楼层元数据。
4. VR 返回的是看房页面链接、如视模型 ID、场景列表，还是可下载全景资源。**公开技能提到 VR，不足以证明可取得等距柱状全景原图。**
5. 是否返回视频、视频封面、下载地址与时长。公开帮助和买房技能中没有找到足以确认这些字段的依据。
6. URL 的有效期、访问条件与素材使用范围。

## 本次访问结果

当前机器未配置 `BEIKE_MCP_API_KEY`，默认凭证文件也不存在。对官方 `https://building.ke.com/mcp` 发起不携带凭证的 `tools/list` 请求，HTTP 为 200 / SSE，JSON-RPC 内返回 `Invalid or missing Authorization header`，未取得工具 schema 或房源数据。HTTP 200 不能视为查询成功；这个结果也不能证明有凭证的用户一定无法调用。

没有获取到一份 AI 平台的真实成功响应，因此该平台结论仍为官方公开说明与 CLI 参数核查，不能标记为“AI 平台实际返回结构已确认”。新增的「图片验真」文档响应有独立来源标识，不填补这个证据缺口。

## 素材选择门槛

上一轮按普通照片自行组织的布里斯班样例及模拟服务已撤下。本轮改用有官方响应依据的图片组准备候选素材；AI 平台适配器暂不实现。真实接入时仍需核对同一房源的详情和物料响应，保留其缺失状态，不把全景原图或视频补进假定的贝壳返回。

这项核查属于制作域的输入准备，不修改已冻结的成片交接类型、SDK 或云端交接接口。

# 抖音发布 worktree 任务说明

## 目标与基线

从同一个公共基础提交创建 `codex/douyin-publish`。先阅读 [共享契约](../12-artifact-exchange.md)、`packages/shared-types/src/artifact.ts` 和 `packages/api-client/src/artifacts.ts`。首期消费平台只考虑抖音；本说明只规定如何接收成片，账号接入与实际发布方式在本 worktree 中另行设计。

消费端入口是一份已验收的 `VideoArtifact`；业务记录固定引用 `ArtifactHandoff.id`，不再通过可变生产任务的“最新 videoUrl”定位视频。

## 本侧负责

- 从共享接口获取成片，展示可消费的成片及验收状态；不从 `Workspace.tasks` 或本机全景检查点拼接真实成果。
- 在明确的交接操作中，用成片 ID、当前验收修订和稳定请求键创建快照；接收视频、封面、可选字幕的资产 ID 和元数据。
- 在消费者自己的数据中保存交接 ID及其固定成片版本。消费者编辑的标题、话题和平台配置不覆盖源成片内容。
- 通过注入的 `LocalMediaAssetResolver` 使用本机文件；不自己猜路径、不导入全景执行器、不把 `fileToken` 当文件路径。
- 对未验收、验收修订变化、文件缺失、错误设备和请求键冲突给出可恢复的结果；通过 `ServiceRequestError.status/code` 判断。
- 把历史交接快照与当前可执行条件分开：在未来执行真实外部操作前，重新核对共享接口和实际文件，不能以旧快照直接证明仍可使用。

## 不属于本侧

不修改文案生成、语音、数字人、渲染和制作任务状态；不自动修复或重新生成源视频；不通过修改公共成片内容保存平台文案；本期不扩展小红书等其他平台。

本任务说明不预设抖音 OAuth、创作者中心操作、上传、定时、审核轮询或重试算法。平台能力和执行方式应在本侧单独确定，不能把夹具返回当作真实发布成功。

## 独立开发方式

使用 `packages/shared-types/fixtures/artifact-handoff.v1.json` 作为固定消费输入，并用 `createArtifactExchange(injectedTransport)` 注入测试适配器。播放或文件访问测试另行提供明确的测试文件和解析器。测试文件不是生产输出，也不代表平台已发布。

在制作侧尚未完成本机注册表时，本侧仍能验证消费边界。联调时替换为真实共享接口和制作侧提供的独立文件解析端口；无需替换消费业务模型。

## 文件与协作边界

主要修改范围：发布中心页面、新增消费侧独立模块及其业务接口/表。`PublishTask` 当前还是旧生产任务/Mock 模型，后续迁移应在本侧明确处理；不能为了复用它反向耦合新成片与制作任务。

公共基础文件和 JSON 夹具冻结，变更先形成双方共用提交。入口文件尽量只增加委托注册，避免把发布实现堆入 `auth.cjs` 或 `main.go`。原有 Mock 演示与真实消费输入保持明确区别。

## 交接验收

1. 不启动制作器，也能用固定交接夹具完成消费边界测试。
2. 只依赖共享成片、资产、交接 ID 和文件解析端口，不读取制作任务内部数据。
3. 新成片版本不会替换已固定的交接；消费者改文案不会修改源成片。
4. 验收变化、文件缺失、错误设备和重复请求都得到明确结果，不静默改用其他视频。
5. 夹具与测试适配器不会造成真实平台副作用，也不会记为真实成功。
6. 共享测试和本侧必要的消费边界测试通过；不以实际生成或实际发布为本公共基础的验收条件。

开发环境与建 worktree 的方式见 [并行开发准备](../13-parallel-worktrees.md)。
